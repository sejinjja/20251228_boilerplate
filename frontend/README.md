# 프런트엔드 (포트 3000) - 게시판 클라이언트

## 개요
- 게시판용 SPA로 백엔드(기본 8080) REST API와 통신합니다.
- 로그인/회원가입/로그아웃 및 JWT 기반 인증 흐름을 제공합니다.
- 인증이 필요한 라우트는 토큰을 요구하며, 미인증 시 로그인 화면으로 이동합니다.

## 실행/빌드
- 요구사항: Node.js 18+와 npm/yarn/pnpm 중 하나.
- 설치: `npm install`
- 개발 서버: `npm run dev` (기본 포트 3000, `PORT`로 오버라이드 가능)
- 빌드: `npm run build`
- 미리보기: `npm run preview`
- 기본 백엔드 주소: `http://localhost:8080` (환경 변수로 설정)

## 환경 변수 예시 (.env.local)
PORT=3000
VITE_API_BASE_URL=http://localhost:8080
VITE_JWT_STORAGE_KEY=forum_access_token
VITE_REFRESH_ENDPOINT=/api/auth/refresh
VITE_PAGE_SIZE_DEFAULT=10

## 라우팅/화면 요구사항
- `/login`: 이메일/비밀번호 로그인. 이미 로그인된 경우 글 목록으로 리다이렉트.
- `/signup`: 회원가입 후 자동 로그인 또는 로그인 화면으로 이동.
- `/posts`: 글 목록, 페이지네이션, 검색(제목+내용+작성자), 태그 필터.
- `/posts/:id`: 상세 보기, 댓글 목록/작성/삭제(본인), 좋아요/싫어요(중복 방지).
- `/posts/new`: 글 작성(로그인 필요). 제목 필수, 본문 최소 10자, 태그 최대 5개.
- `/posts/:id/edit`: 글 수정/삭제(작성자 또는 관리자만).
- `/profile`: 내 정보 보기/수정, 비밀번호 변경.

## 인증/보안 흐름
- 로그인 성공 시 수신한 JWT를 안전한 저장소(메모리 우선, 필요 시 localStorage)와 앱 상태에 보관합니다.
- 모든 API 요청은 `Authorization: Bearer <accessToken>` 헤더를 붙입니다.
- 401/419 등의 만료 응답 시 `/api/auth/refresh`로 재발급 시도 후 재시도, 실패 시 로그아웃.
- 로그아웃 시 모든 토큰/유저 상태를 초기화합니다.
- XSS 예방을 위해 사용자 입력 렌더링 시 escape/sanitize 처리, `innerHTML` 사용 지양.

## 게시판 UX/기능 제약
- 목록: 제목, 작성자, 작성일, 조회수, 댓글 수, 태그 노출. 페이지 크기 기본 10, 최대 50.
- 정렬: 최신순 기본, 인기순(조회수/좋아요) 선택 가능.
- 상세: 본문, 태그, 첨부(옵션), 작성/수정일, 작성자, 좋아요/싫어요, 댓글.
- 댓글: CRUD 가능(로그인 필요). 본인/관리자만 수정·삭제.
- 입력 검증: 제목 최대 120자, 본문 최대 10,000자, 태그 최대 5개(각 20자), 첨부는 백엔드 정책 따름.
- 에러/로딩: 전역 로딩, 폼 단위 에러 메시지, 권한 부족/만료 시 안내.

## 품질 체크리스트
- API 모듈에서 백엔드 경로, 헤더, 에러 처리를 일원화합니다.
- 보호 라우트는 가드/HOC로 공통 처리하고, 비보호 라우트는 로그인 상태를 검사하여 리다이렉트.
- 폼은 클라이언트 검증 후 제출하고, 서버 검증 에러는 필드별 메시지로 표기.
- 테스트 권장: 인증 흐름(로그인/만료/리프레시), 권한별 라우팅, 게시글/댓글 CRUD UX.
